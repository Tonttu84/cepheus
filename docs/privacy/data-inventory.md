# Personal Data Inventory — Cepheus Build

> **Draft for a hackathon demonstration. Written by an AI agent, not reviewed by a lawyer, not legal advice.**

This inventory documents every category of personal data handled by the Cepheus post-TMS follow-up build. Every row is derived directly from the application code, storage ports, and database models in this repository.

## 2. What Is Deliberately NOT Stored (and Why)

The Cepheus build enforces strict negative boundaries. The following data categories are intentionally refused, excluded, or discarded by design:

1. **Direct Patient Identifiers (Names, Social Security Numbers, Phone Numbers, Addresses):**
   - *Decision:* Decision D20 established that patients are strictly pseudonymous. No patient names, phone numbers, email addresses, dates of birth, or national identity codes (henkilötunnus / HETU) are stored in this database.
   - *Code Evidence:* `Participant` model in `prisma/schema.prisma` (lines 70–98) contains only `participantCode` and `externalId`. The clinic maintains the re-identification key in its separate clinical system outside this database.
2. **Individual Questionnaire Answers (PHQ-9 Items 1–8, GAD-7 Items 1–7):**
   - *Decision:* Decision D45 establishes that individual questionnaire answers are not stored until a feature specifically requires them. While a questionnaire is in progress, the server holds its item answers in volatile server memory only; when the round is completed, the memory is cleared and only the calculated total score is stored in the database.
   - *Code Evidence:* `src/server/db/answer-store.ts`, `src/usecases/submit-phq9-answer.ts`, and `src/server/db/__tests__/answer-store.test.ts`. The database schema columns for item answers (`item1Interest` through `item8Psychomotor`) default to `null` unless the `STORE_ITEM_ANSWERS` setting is explicitly enabled.
3. **Raw Video Frames, Images, and Camera Feeds:**
   - *Decision:* Decisions D15 and D41 mandate that camera input is processed entirely on the user's device and only derived summary statistics are stored, never video or pictures.
   - *Code Evidence:* MediaPipe Face Landmarker runs locally in the client browser (`src/components/camera/use-camera-session.ts`, `src/domain/camera/frame.ts`). The API route rejects any payload containing image or video buffers (`src/domain/arduino/evaluate.ts`, `containsRawMediaFields`), verified by `src/__tests__/no-raw-logging.test.ts`.
4. **Raw Audio Recordings and Speech Transcripts:**
   - *Decision:* Decisions D41 and D45 mandate that microphone and voice inputs are processed on the device; only numerical speech timing (syllable counts, pause counts) or local speech-to-integer mappings are transmitted.
   - *Code Evidence:* Edge voice kiosk (`hardware/uno-q/voice_kiosk.py`, `src/domain/arduino/voice-choice.ts`) maps spoken answers to fixed numeric options locally; no raw audio or text transcripts are sent to the server.
5. **Browser Storage (localStorage, sessionStorage, IndexedDB):**
   - *Decision:* Decisions D17 and D45 specify that the phone is only a display terminal and stores nothing on the client device except an encrypted `HttpOnly` session cookie.
   - *Code Evidence:* Enforced by automated tests in `src/__tests__/no-local-storage.test.ts` and `e2e/no-local-storage.spec.ts`.
6. **Free-Text Clinical Notes and Open Messaging:**
   - *Decision:* To eliminate unstructured personal and third-party data leaks, free-text clinical notes (`freeTextNote` and `summaryNote`) were removed from the database schema.
   - *Code Evidence:* `NurseCallRecord` in `prisma/schema.prisma` (lines 616–646) accepts only structured enumerations (`outcomeTier`, `actionTaken`, `medicationChecked`), preventing free-text narrative storage.
7. **Real Bank Accounts, Credit Cards, and Payment Information:**
   - *Decision:* Decision D48 keeps the 1-euro rewards strictly simulated, avoiding the collection of IBANs, bank accounts, or financial records.
   - *Code Evidence:* `src/domain/rewards/` and `src/usecases/rewards/`.
